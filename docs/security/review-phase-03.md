### 2.1 Identity & Session Management (`TM-ID-01`..`TM-ID-06` + `TM-ID-07` Alias)

| Threat ID | Threat Summary & Severity | Exact Specification Controls & Line References | Design Coverage Status |
|---|---|---|---|
| **TM-ID-01** | **Brute Force & Credential Stuffing** (`High`) | - **Password Hashing & Lockout**: `ADR-003` (`L26–L28`) specifies ASP.NET Core Identity `PasswordHasher<ApplicationUser>` (PBKDF2-HMAC-SHA512) and lockout of `15 minutes` after `5` failed login attempts.<br>- **Database Columns**: `06-DATABASE-ERD.md` (`L148–L158`) defines `identity.Users.PasswordHash nvarchar(512)`, `LockoutEnabled bit DEFAULT 1`, `LockoutEnd datetimeoffset(7)`, and `AccessFailedCount int`.<br>- **Rate Limiting**: `ADR-003` (`L29`) and `07-API-SPECIFICATION.md` (`L37`, `L124`, `L126`, `L127`, `L130`, `L131`) enforce the `auth` rate-limit policy (`5 req / min` per IP + normalized email) returning HTTP `429 RATE_LIMITED` with `Retry-After` on `/auth/register`, `/auth/login`, `/auth/forgot-password`, `/auth/resend-verification`, and `/auth/reset-password`. | **PASS (Covered)** |
| **TM-ID-02** | **Account Enumeration** (`Medium`) | - **Non-Enumerating Endpoints**: `ADR-003` (`L30`) and `07-API-SPECIFICATION.md` (`L126`, `L130`) specify that `POST /auth/resend-verification` and `POST /auth/forgot-password` always return `202 Accepted` with identical body `{ accepted: true }` regardless of whether the email is registered.<br>- **Generic Login Error**: `07-API-SPECIFICATION.md` (`L80`, `L127`) returns `401 UNAUTHENTICATED` without distinguishing unregistered email vs. wrong password. | **PASS (Covered)** |
| **TM-ID-03** | **JWT Forgery / Algorithm Confusion / Weak Signing Secret** (`Critical`) | - **JWT Validation & Secret Entropy**: `ADR-003` (`L32–L36`) mandates a 15-minute (`900s`) lifetime, explicit `HS256` signing with a $\ge 256\text{-bit}$ secret from `JWT_SIGNING_KEY` env var, and validation of `Issuer`, `Audience`, `Lifetime` (`ClockSkew = 30s`), and signature.<br>- **Minimal Claims**: `ADR-003` (`L35–L36`) and `permissions-seed.md` (`L67`) include only `sub`, `email`, `name`, `role`, and `jti` in the JWT—never the permission array. | **PASS (Covered)** |
| **TM-ID-04** | **Refresh Token Theft, Replay & Family Compromise** (`Critical`) | - **Hashed Storage & Family Tracking**: `ADR-003` (`L39–L47`) and `06-DATABASE-ERD.md` (`L248–L270`) persist only the SHA-256 hex `TokenHash` (`UQ_RefreshTokens_TokenHash`) of 32 cryptographically random bytes in `identity.RefreshTokens` alongside `FamilyId`, `ExpiresAt`, `RevokedAt`, and `ReplacedByTokenId`.<br>- **Rotation & Reuse Detection**: `ADR-003` (`L46–L47`) and `07-API-SPECIFICATION.md` (`L90`, `L128`) rotate the token on every `POST /auth/refresh`; if an already-revoked token is re-presented, all tokens in that `FamilyId` are immediately revoked (`401 REFRESH_TOKEN_INVALID`).<br>- **CSRF Defense-in-Depth**: `ADR-003` (`L45`) and `07-API-SPECIFICATION.md` (`L128`) require header `X-Requested-With: XMLHttpRequest` on `POST /auth/refresh` in addition to `SameSite=Strict`. | **PASS (Covered)** |
| **TM-ID-05** | **XSS Token Exfiltration via `localStorage`** (`High`) | - **In-Memory Access Token & `HttpOnly` Refresh Cookie**: `ADR-003` (`L37`, `L41–L42`, `L63–L64`), `05-SYSTEM-ARCHITECTURE.md` (`L126`), and `07-API-SPECIFICATION.md` (`L41–L42`) forbid storing tokens in `localStorage`/`sessionStorage`/URLs; `accessToken` is kept strictly in JS memory, and `gh_refresh` is issued with `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth; Max-Age=1209600`. | **PASS (Covered)** |
| **TM-ID-06** | **Permission Cache Staleness & Unrevoked Access** (`High`) | - **Server-Side Cache & Immediate Eviction**: `ADR-003` (`L49–L55`), `05-SYSTEM-ARCHITECTURE.md` (`L128–L133`), and `permissions-seed.md` (`L62–L69`) resolve `EffectivePermissions(u)` server-side in `PermissionAuthorizationHandler` via `IMemoryCache` (`perm:user:{userId}`, TTL `60s`) while checking `u.Status == Active && u.DeletedAt == null`.<br>- **Cross-Module Cache Invalidation & Audit**: `module-contracts.md` (`L119–L127`, `IPermissionService.InvalidateUserPermissionsCache` / `InvalidateAllPermissionsCache`), `events.md` (`L91–L92`, `L358–L386`, `RolePermissionsUpdatedEvent` & `CustomerLockedEvent`), and `07-API-SPECIFICATION.md` (`L265`, `L271`, `L272`, `L275`) immediately evict cached permissions, revoke active refresh tokens on lock/password change, and write `audit.AuditLogs`. | **PASS (Covered)** |
| *(Alias)* **TM-ID-07** | **Customer PII Anonymization & Account Lifecycle (`NFR-010`)** (`High`) | - **Admin-Only Anonymization Contract**: `module-contracts.md` (`L99–L102`, `L114–L116`, `AnonymizeUserIdentityCommand`), `permissions-seed.md` (`L47`, `staff.manage`), `07-API-SPECIFICATION.md` (`L267`, `POST /admin/customers/{id}/anonymize`), and `06-DATABASE-ERD.md` (`L159`, `L1492`) scrub `Email`, `NormalizedEmail`, `FullName`, and `PhoneNumber` in `identity.Users`, soft-delete `customers.Addresses`, revoke all `RefreshTokens`, set `Status = 'Disabled'` and `DeletedAt = now`, reject if active non-terminal orders exist (`409 CONFLICT`), and preserve historical `ordering.Orders` financial records. | **PASS (Covered)** |

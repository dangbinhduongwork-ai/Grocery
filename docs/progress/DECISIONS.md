| **DEC-015** | 2026-11-15 | 05 | Secure Identity, Dynamic RBAC, Token Rotation, and Hardened Anti-Enumeration Auth | 1) Password hashing uses ASP.NET Core `PasswordHasher<User>` (PBKDF2-HMAC-SHA512, 100k iterations) with a $\ge 10$ character complexity policy; lockout triggers after 5 failed attempts for 15 minutes.<br>2) Access tokens have a 15-minute lifetime (`sub`, `roles`, `jti`, no permissions in claims per `ADR-003`). Refresh tokens are 512-bit random values stored as SHA-256 hashes at rest in `identity.RefreshTokens`, tracking `FamilyId`. Replaying an invalidated token revokes the entire family immediately (theft detection).<br>3) Cookie `gh_refresh` issued with `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`, and `/auth/refresh` strictly enforces `X-Requested-With: XMLHttpRequest`.<br>4) Dynamic authorization evaluates the 29 seeded permissions via cached `IPermissionService` (TTL $\le 60$s in `IMemoryCache`), with immediate cache eviction on staff role/permission updates. Built-in Admin role permissions are immutable.<br>5) Anti-enumeration enforced on `/auth/forgot-password` and `/auth/resend-verification` (returns HTTP 202 regardless of user existence). Hardening per CR-002: single-use tokens redacted from standard logs, timed tokens expire in 1h (reset) and 24h (verification), and production JWT signing key overrides default development key. | **CONFIRMED** | `docs/progress/phase-05-report.md`, `docs/security/review-phase-05.md`, `docs/security/rbac-test-phase-05.md` |

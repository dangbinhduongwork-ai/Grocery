# Database rules

- Single `GroceryHubDbContext`; each module owns a SQL schema (`identity`, `customers`, `catalog`, `inventory`, `purchasing`, `promotions`, `cart`, `ordering`, `payments`, `reviews`, `audit`). Entity configurations (`IEntityTypeConfiguration<T>`) live in the owning module and are discovered by assembly scan.
- No foreign keys across module schemas except to `identity.Users(Id)` by value where documented in `docs/spec/06-DATABASE-ERD.md`; cross-module references are plain Guid columns plus indexes.
- Every table: `Id`, `CreatedAt`, `UpdatedAt` (set by interceptor), and `RowVersion` (`rowversion`) on aggregates that face concurrent writes (stock, orders, payments, coupons).
- Money columns `bigint` (VND). Quantities `int`. Strings: explicit max lengths; Vietnamese text columns use `nvarchar`. Case/accents: for search use a computed normalized column (accent-stripped lower) or full-text search with the Vietnamese-compatible configuration — decide in Phase 6 with evidence.
- Unique constraints are part of correctness: `Orders.OrderNumber`, `Payments.PaymentCode`, `PaymentWebhookEvents.ProviderTransactionId`, `Users.NormalizedEmail`, `Products.Sku`, `Products.Slug`, `Coupons.Code`, `IdempotencyKeys(Key, Scope)`.
- Migrations: generated by EF Core, one per logical change, reviewed, never edited after merge. Names: `YYYYMMDD_<Module>_<Change>`. Never `Database.Migrate()` on app start in Production; use a migration bundle/one-off container.
- Seed data: reference data only (roles, permissions, provinces/wards, default shipping rates, order-status lookup). Sample products are a separate, clearly-marked Development-only seeder that is never executed in Production.
- Stock updates must be atomic and race-safe: conditional `UPDATE ... WHERE QuantityOnHand - QuantityReserved >= @qty` (via `ExecuteUpdateAsync`) or rowversion optimistic concurrency with retry. Prove with a concurrency integration test.
- Index every FK and every column used by filters/sorts on list endpoints; justify each index in the migration PR description. Check query plans for the product search and order list queries.
- Soft delete only where business needs history (Products, Categories, Brands, Suppliers, Users). Orders/payments/audit logs are never deleted.
- Backups and restore procedure documented and tested in Phase 12.
